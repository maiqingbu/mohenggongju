# NovelStudio v0.2 设计参考——七大竞品分析后的改进方向

> 基于对 plotbunni、inkos、AI-Novel-Writing-Assistant 等项目的源码级分析

---

## 一、当前 NovelStudio 已有的优势（不要丢）

我们已有的东西和竞品对比如下：

| 我们的资产 | 对标竞品 | 评价 |
|-----------|---------|------|
| 总纲→卷纲→章纲三层模板 | inkos 的 author_intent + current_focus + volume_outline | 我们更结构化 |
| 8种章节类型规范 + 逻辑控制台 | inkos 的 33 维审计 | 我们更偏"写作前"的规划 |
| Tauri 桌面应用 | AI-NWA 的 Electron | 技术栈更现代 |

**我们的差距不在规划层，在"从规划到正文"的执行链路上。**

---

## 二、最值得借鉴的三个设计

### 1. inkos 的「输入治理」模式 —— 对应我们的总纲/卷纲/章纲

inkos 把"给 AI 的上下文"拆成三层，层层编译：

```
author_intent.md      ← 我们已有的「总纲-核心灵感锚定」
    ↓
current_focus.md      ← 我们已有的「卷纲-本卷主角提升目标」
    ↓
chapter-XXXX.intent.md  ← 我们已有的「章纲-逻辑控制台」
    ↓
context.json + rule-stack.yaml  ← 【我们没有】编译后的上下文
    ↓
trace.json           ← 【我们没有】调试用追踪
```

**建议**：在章纲和 AI 写作之间加一个「编译层」：
- 章纲填写完后 → 自动编译成 `chapter-N.context.md`（提取角色/场景/伏笔/爽点）
- 不是把所有总纲一股脑塞进 prompt，而是按章对照卷纲 Phase 位置，只注入相关上下文
- 编译结果可人工预览和微调，避免 AI 拿到错误上下文滚雪球

### 2. inkos 的「7 真相文件」—— 对应我们的「人物生态树 + 四大升级线」

inkos 用 7 个文件追踪整本书的运行状态：

| inkos 真相文件 | 我们对应的部分 | 差距 |
|---------------|--------------|------|
| current_state.md（角色位置/关系/已知信息） | 人物生态树 | 我们是静态表，inkos 是动态更新的 |
| particle_ledger.md（物品/金钱/物资） | 无 | 需要新增 |
| pending_hooks.md（未闭合伏笔） | 无 | 需要新增 |
| chapter_summaries.md（章摘要+出场人物+状态变化） | 章纲-本章收益 | 我们是规划，inkos 是事后的 |
| subplot_board.md（支线进度） | 总纲-四大升级线 | 我们是设计稿，inkos 是运行时状态 |
| emotional_arcs.md（角色情感弧线） | 总纲-情感/羁绊线 | 同上 |
| character_matrix.md（角色交互矩阵） | 人物生态树 | 同上 |

**建议**：把总纲里的「人物生态树」「四大升级线」从静态设计变成**可追踪的运行时状态**。每写完一章，自动更新：
- 哪个角色的伏笔推进了一步
- 哪个物品被消耗/转移
- 哪条支线的进度条走了多少
- 哪个情感关系发生了温度变化

这个"事后结算"反过来喂给下一章的 context，防止角色失忆。

### 3. AI-Novel-Writing-Assistant 的「导演式开书」—— 对应我们的总纲流程

AI-NWA 把"从灵感→可开写"设计成一条连续推进链：

```
灵感一句话
  → AI 生成多套整本方向方案
  → 用户选择方案 + 标题组
  → 项目设定（题材/卖点/读者感受/前30章承诺）
  → 故事宏观规划（主线/对立/兑现节奏）
  → 角色准备（核心阵容/关系网/缺席风险）
  → 卷战略 + 卷骨架
  → 节奏拆章（落到具体章节标题+摘要）
  → 章节执行
```

**我们的总纲模板已经覆盖了大部分步骤**，但缺少中间两个：
- 「项目设定」页——把题材/卖点/读者预期/前N章承诺单独成页，作为 AI 生成的方向锚
- 「故事宏观规划」——在分卷之前先定整个故事的主引擎和兑现节奏

**建议**：在总纲模板中新增「书级设定」和「宏观规划」两个区块，放在等级体系之前。

## 三、具体可落地的改进项（按优先级）

### P0 —— 马上能做

1. **总纲模板加两个新区块**
   - 「书级设定」：题材、卖点、目标读者感受、前N章承诺
   - 「宏观叙事引擎」：故事主引擎（是什么驱动剧情）、长期对立、兑现节奏

2. **新增伏笔追踪文件模板**
   - 参考 inkos 的 `pending_hooks.md`，设计一个「伏笔账本」
   - 字段：伏笔ID、埋设章节、预期回收章节、当前状态、关联角色

3. **章纲模板加「编译输出」区**
   - 章纲填完后，自动拼接一个「AI 上下文快照」：角色在谁手里、当前地图、活跃伏笔、本Phase位置
   - 这个快照就是给 AI 写正文时用的 context

### P1 —— 需要开发

4. **「运行时状态」追踪系统**
   - 每写完一章，从正文自动提取（或手动标注）：出场角色、位置变化、物品流转、伏笔推进
   - 存为结构化数据（JSON），不做 Markdown 手工维护
   - 下一次写章时，编译成 context 注入 prompt

5. **章节类型—爽感—博弈 自动推荐**
   - 基于类型规范中的分布建议，在卷纲阶段自动计算本章应该用哪种类型
   - 防止连续打脸或装逼泛滥

### P2 —— 远期

6. **Agent 管线**
   - 参考 inkos 的设计：规划Agent → 编排Agent → 写作Agent → 审计Agent → 修订Agent
   - 每个 Agent 可以用不同的模型（写作用贵的、审计用便宜的）

7. **写法引擎**
   - 上传参考文本 → AI 提取写法特征（句长分布/词汇偏好/节奏模式）→ 保存为写法资产 → 绑定到指定书

## 四、模板文件的改造清单

| 文件 | 改动 |
|------|------|
| `总纲模板.md` | + 书级设定、+ 宏观叙事引擎、+ 伏笔账本入口 |
| `卷纲模板.md` | + 类型自动分布推荐、+ Phase 位置追踪 |
| `章纲模板.md` | + context 编译输出区、+ 事后结算区（本章推进了什么） |
| 新增：`伏笔账本模板.md` | 字段：伏笔ID、埋设章、预期回收章、状态、关联角色/物品 |
| 新增：`世界状态模板.md` | 角色位置追踪、物品流转、关系温度、支线进度 |
